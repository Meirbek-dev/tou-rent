## 2. Целевая топология (упрощенная, один хост университета)

```
пользователи ── HTTPS ──▶ Caddy (rent.tou.edu.kz, TLS)
                            ├─▶ web  - TanStack Start SSR (публичный портал + кабинеты)
                            └─▶ api  - Rust/Axum (REST + SSE-уведомления + WS-аукцион)
                                  ├─▶ PostgreSQL 18   (все авторитетные данные, RLS, аудит)
                                  ├─▶ Redis 8         (сессии, rate-limit, pub/sub аукциона, очереди apalis)
                                  └─▶ MinIO           (файлы: сканы, PDF-протоколы; бакет public / dossiers)
                            jobs - apalis-воркер (дедлайны-обязательства, снятие публикаций, отложенные задачи)
                            otel-lgtm - Grafana+Loki+Tempo+Prometheus в одном контейнере
                            keycloak - контур 2 (LDAP-федерация с AD)
Zoom (внешний)  - ссылка на конференцию/запись хранится в карточке торгов
GitLab (self-managed) - код, CI, Container Registry, деплой по SSH на хост
```

Все контейнеры - один `docker-compose.prod.yml`, том PostgreSQL и MinIO на дисках хоста, pgBackRest-бэкап в MinIO ежесуточно.

## 3. Архитектурные принципы (без изменений по сути, усилены под «без ревью»)

Принципы v1 сохраняются: compile-time прежде runtime; БД - последний рубеж; один источник истины на факт; чистое ядро без IO; сроки - данные (obligations engine); bleeding edge с якорями отката.

Новое следствие отсутствия человеческого ревью: **пайплайн = ревьюер**. Любое свойство системы, которое раньше «проверил бы сеньор», обязано быть выражено как гейт (§ 8). Файлы, определяющие сами гейты (CI-конфиг, specs, AGENTS.md, снапшоты, примененные миграции), выделены в защищенные пути: MR, трогающий их, требует аппрува инженера-контролера - это единственная ручная контрольная точка.

│  └─ e2e/                 # Playwright: сценарии Правил
├─ specs/                  # INVENTORY.md (INV-###), BACKLOG.md, QUESTIONS.md, ASSUMPTIONS.md, adr/
├─ infra/compose/          # docker-compose.dev.yml / prod.yml, Caddyfile, deploy.sh

Bun ≥1.3 - пакетный менеджер и раннер; Turborepo 2 - оркестрация, кеш пайплайна складывается в GitLab cache. Rust-задачи подключены к графу Turbo через package.json-обертки (`"lint": "cargo clippy --all-targets -- -D warnings"` и т. п.), поэтому у агента одна команда самопроверки: `bun turbo check` (= codegen → lint → typecheck → test).

## 6. Данные

PostgreSQL 18, схемы `core` / `audit` / `refdata`. Миграции `sqlx migrate`, линт Squawk. Ключевые инварианты - на уровне СУБД:

```sql
-- Переходы статусов только по таблице разрешений (триггер, п. 5–11 Правил)
-- EXCLUDE-ограничение: один объект не сдается на пересекающиеся периоды
ALTER TABLE core.contracts ADD CONSTRAINT no_overlapping_lease
  EXCLUDE USING gist (object_id WITH =, lease_period WITH &&)
  WHERE (status IN ('signing','active'));

-- Журнал регистрации (п. 37–39): append-only (REVOKE UPDATE/DELETE),
-- вставка запрещена после дедлайна, seq монотонна в рамках тендера (уникальность (tender_id, seq))

-- Запечатанность цен (п. 40): ценовые предложения в отдельной таблице,
-- RLS запрещает SELECT всем ролям до события вскрытия (opened_at IS NOT NULL);
-- вскрытие - отдельная API-операция секретаря, пишется в audit.log.
-- Контур 2: + pgp_sym_encrypt с ключом тендера.

-- Ставки аукциона: append-only; CHECK amount > 0; триггер amount >= prev_max + step
-- Депозитная книга: двойная запись, CHECK (debit=0 OR credit=0), баланс не < 0

-- audit.log: append-only, hash-цепочка (row_hash = sha256(prev_hash || payload)),
-- триггеры на всех критичных таблицах (перечень INV-AUDIT, проверяется тестом G15)
```

Справочники в `refdata`: коэффициенты Прил. 4 (версионированные, `effective_from`), МРП по годам, производственный календарь РК (для `add_business_days`, реализация SQL + Rust с тестом паритета), таблица переходов статусов.

Redis - только эфемерное (сессии, pub/sub, очереди, rate-limit): потеря инстанса не теряет данных. MinIO - `public` (опубликованные PDF, снятие через 6 мес джобом) и `dossiers` (все материалы тендера; Object Lock ≥5 лет включается в контуре 3).

## 7. Контракт и фронтенд

Цепочка кодогенерации (гейт «codegen без диффа» - G5): Rust/utoipa → `openapi.json` → `openapi-typescript` → `packages/api-client` (типы + `openapi-fetch` + `openapi-react-query`). Ручные DTO во фронте запрещены (Biome `noRestrictedImports`). Runtime-валидация форм - Valibot 1.x через Standard Schema (одна схема - и TanStack Form, и серверная функция). WS-сообщения аукциона типизируются из Rust через schemars.

| Область        | Инструмент                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Фреймворк      | React 19 + TanStack Start v1 (SSR публичного портала, стриминг)                                                                                                       |
| Данные/роутинг | TanStack Router + Query + Table + Form + Virtual; фильтры реестров - в typed search-параметрах URL                                                                    |
| UI             | shadcn/ui (реестр в `packages/ui`), Tailwind 4, шрифт Inter, стандартная тема shadcn (брендинг-токены университета подключаются позже без переписывания компонентов)  |
| i18n           | Paraglide JS 2: kk / ru / en с первого релиза; типобезопасные ключи; CI-проверка полноты (контур 1: ru - эталон, kk/en допускают черновой перевод с пометкой `draft`) |
| Язык/сборка    | TypeScript 7 (tsgo, пин версии, откат на 5.9 задокументирован), Vite+ / rolldown-vite, Vitest 3, Biome 2, Knip, dependency-cruiser                                    |

Публичный контур (без авторизации, SSR, индексируется): реестр объявлений, карточка тендера с документацией, свободные площади, опубликованные протоколы и обоснования особого порядка (п. 6, 76, 90, 97). Кабинеты по ролям - route-группы с проверкой роли в загрузчике: участник, организатор, секретарь, член комиссии, Правление, финансы, админ.
