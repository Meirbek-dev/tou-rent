# Техническое задание TOU.Rent v1.0

Заказчик: Департамент цифрового развития и внедрения ИИ НАО «Торайгыров университет»
Исполнитель кода: ИИ-агент (Claude Fable 5 / Claude Code) под контролем 1–2 инженеров. Человеческого ревью кода нет - приемка автоматическая, через гейты CI (арх. § 8) и критерии настоящего ТЗ.
Документы-основания: (1) Правила передачи недвижимого имущества в имущественный наем, реш. СД № 1 от 30.01.2026 - далее «Правила», ссылки вида «п. N»; (2) Техническая архитектура v2 (`tou-rent-architecture-v2.md`) - далее «Архитектура». Стек, топология, структура репозитория, гейты CI берутся из Архитектуры без изменений.

Правило чтения для агента: требования имеют ID (`FR-`, `NFR-`, `INV-`). Каждый коммит ссылается минимум на один ID. Если требование неоднозначно - действуй по § 12 регламента (Приложение А): зафиксируй допущение в `specs/ASSUMPTIONS.md` и продолжай, не блокируясь.

## 1. Назначение системы

Веб-платформа `rent.tou.edu.kz`, автоматизирующая передачу недвижимого имущества университета в аренду по Правилам: публикация объявлений, прием и регистрация тендерных заявок, работа тендерной комиссии, двухэтапный тендер с онлайн-торгами на повышение, формирование протоколов и договорных документов, учет гарантийных взносов и депозитов, особый порядок (раздел 12), контроль процессуальных сроков, публичность и аудит.

## 2. Периметр

**В объеме (по контурам, см. § 9):** реестр объектов; калькулятор ставок по Прил. 4; жизненный цикл тендера (разделы 2, 4–11 Правил); онлайн-аукцион (полноценный WS-интерфейс подачи ставок участниками); протоколы и печатные формы PDF (Typst) по Прил. 1–3, 5–12; договорный конвейер и акты (без ЭЦП - печать и загрузка скана); депозитная книга с ручным подтверждением оплат оператором финблока; особый порядок (раздел 12); земельные участки (раздел 14, упрощенно); in-app уведомления; публичный портал; аудит с hash-цепочкой; i18n kk/ru/en.

**Вне объема (не проектировать, не закладывать код):** интеграция с веб-порталом госзакупок (раздел 13 Правил) - соответствующие процессы остаются вне системы; ЭЦП НУЦ РК (закладывается только интерфейс-заглушка `SigningProvider`); интеграции 1С/банк/СЭД; Email/SMS/Telegram-доставка (абстракция каналов - да, реализация - контур 3+); миграция исторических данных; мобильные приложения; Kubernetes.

## 3. Роли и права

Роли фиксированы enum'ом `Role` в `crates/domain` (исчерпывающий match в политике доступа, INV-POL-01):

| Роль          | Кто                                              | Ключевые права                                                                                          |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `guest`       | Аноним                                           | Чтение публичного портала                                                                               |
| `participant` | Внешний участник (email-регистрация, без ЭЦП)    | Подача/отзыв заявки до дедлайна, участие в торгах по своим лотам, свои документы и уведомления          |
| `organizer`   | Юридическая служба (организатор тендера, п. 2.4) | Объекты, тендеры, объявления, тендерная документация, отмена/повтор тендера                             |
| `secretary`   | Секретарь тендерной комиссии (п. 17)             | Журнал регистрации, вскрытие заявок, ведение заседаний, формирование протоколов, уведомление участников |
| `commission`  | Член тендерной комиссии                          | Просмотр заявок после вскрытия, голосование «за/против», особое мнение, декларация конфликта интересов  |
| `board`       | Член Правления                                   | Решения по особому порядку, форме тендеров, спорным случаям                                             |
| `finance`     | Департамент финансов и учета                     | Подтверждение поступления взносов/депозитов, возвраты, депозитная книга                                 |
| `admin`       | Департамент цифрового развития                   | Пользователи, роли, справочники (коэффициенты, МРП, календарь), настройки                               |

Матрица «роль × действие» генерируется тестом из политики и хранится снапшотом (изменение - только через инженера, арх. § 8).

## 6. Модель данных (ядро; детальную DDL агент выводит сам, инварианты обязательны)

`core`: users, role_grants, objects, tenders, lots, tender_docs (версии, FR-304), applications, application_files, price_proposals (RLS до вскрытия - INV-040), journal_entries (append-only, (tender_id,seq) unique - INV-037), commissions, commission_members, coi_declarations, sessions_meetings, votes, protocols (тип: допуск/итоги/несостоявшийся/победитель№2), auctions, bids (append-only, шаг - INV-063), contracts (lease_period tstzrange, EXCLUDE - INV-DB-02), contract_checklists, acts, ledger_accounts, ledger_entries (INV-DB-05), obligations, notifications, special_requests, dossier_items.
`refdata`: mrp, rate_coefficients, holidays, tender_status_transitions, rejection_reasons.
`audit`: log (hash-цепочка - INV-A01).

Все ID - uuid v7 (`uuidv7()` PG18). Деньги - `numeric(14,2)` KZT. Времена - `timestamptz`.

## 7. API и контракт

REST под `/api/v1`, OpenAPI 3.1 из utoipa - единственный источник; SSE `/api/v1/events` (уведомления); WS `/api/v1/auctions/{id}/room`. Конвенции: kebab-case пути, cursor-пагинация, идемпотентность мутаций через `Idempotency-Key` для ставок и подачи заявок; ошибки problem+json c машинным `code` (enum, попадает в контракт). Фронт использует только `@tou/api-client` (сгенерированный) - гейт G5/G7.

## 8. UI

## 10. Приемка
