# TOU.Rent

Платформа передачи недвижимого имущества Торайгыров университета в имущественный наем:
объявления, тендерные заявки, онлайн-торги, протоколы, договоры (rent.tou.edu.kz).

Документы-основания: [ТЗ v1.0](docs/tou-rent-tz-v1.md) (требования) · [ТЗ v2.0](docs/tou-rent-tz-v2.md) (состояние и оставшиеся работы) · [Архитектура v3](docs/tou-rent-architecture-v3.md) (фактическая; [v2](docs/tou-rent-architecture-v2.md) - история замысла) · регламент агента - [AGENTS.md](AGENTS.md) · допущения и реестры - [specs/](specs/).

              локально - пропуск, в пайплайне - ошибка)

packages/
  api-client/ @tou/api-client - сгенерированный клиент API (openapi-typescript), руками не править

## Что закрыто

Работа идет контурами (ТЗ § 9, арх. § 9); состав и статус каждой задачи -
в [specs/BACKLOG.md](specs/BACKLOG.md), запись на каждую - в [CHANGELOG.md](CHANGELOG.md).

- **Контур 1 (T0–T17)** - объекты и расчет ставки Прил. 4, тендер с лотами
  и публикация, заявка с запечатанной ценой и журнал регистрации, вскрытие
  и допуск, аукционная WS-комната, протоколы, публичный портал, уведомления,
  i18n kk/ru/en, деплой.
- **Контур 2 (T18–T32)** - внешний вход (Zitadel/AD), комиссия с кворумом
  и голосованием, полный регламент торгов, двигатель сроков, депозитная
  книга, договорный конвейер с актами и уклонением, несостоявшийся тендер
  и повтор, шифрование цен, досье тендера с выгрузкой архивом.
- **Контур 3 (T33–T44)** - особый порядок раздела 12 (13 категорий, заявка
  Прил. 3, заключение подразделения, решение Правления, конкуренция заявок,
  инвестиционные договоры, льготные схемы), досье решений и WORM-хранение
  (5 лет тендерные материалы, 3 года решения), публикации особого порядка
  на портале, земельные участки раздела 14, допсоглашения с diff-контролем
  защищенных условий, отчетность (реестры решений, договоров и поступлений
  с выгрузкой CSV).

Не сделано осознанно: T41 - внешние каналы уведомлений (email/Telegram,
FR-1303) пропущена по решению заказчика; пропуск объявлен в гейте
трассировки требований, а не молчанием.

- **Контур 4 (T45–T70)** - производственная готовность: живой пайплайн и
  реальный деплой, типизированные SQL-запросы, бэкап и восстановление,
  секреты, кабинет админа со справочниками, редактирование ПДн в логах,
  нагрузочное и доступностное подтверждение. Состав, критический разбор
  состояния («что значит выполнено») и порядок - [ТЗ v2.0](docs/tou-rent-tz-v2.md).
  Главное ограничение: пайплайн ни разу не прогонялся на живом раннере,
  деплой на `rent.tou.edu.kz` не выполнялся.

## Быстрый старт

```bash
vp install                 # зависимости (Bun-workspace); prepare ставит git-хуки (vp config)
vp run stack:up            # дев-стенд: Postgres/Redis/RustFS + api (миграции - автоматически)
vp run dev                 # web dev-сервер на :3000 (turbo → vp dev)
```

API собирается и работает в контейнере (compose-профиль `api`) и слушает :8080:
health - `/api/v1/healthz`, контракт - `/api/v1/openapi.json`. Только инфраструктура,
без api - `podman compose -f infra/compose/docker-compose.dev.yml up -d`.

```bash
vp run api:restart         # перезапуск api после правок Rust (cargo run перекомпилирует)
vp run api:logs            # логи api
vp run api:migrate         # только миграции (одноразовый контейнер)
vp run stack:down          # остановить стенд целиком
```

Сборочный кеш Rust живет в томе `tou-rent-target` и растет неограниченно:
cargo не вытесняет старые артефакты, а прогоны с разными наборами фич их
множат (за три дня работы том дорос до 101 ГБ). Кеш регенерируемый, чистить
его безопасно - платой будет пересборка:

```bash
vp run cache:size          # сколько занято: всего, deps, инкрементальные данные
vp run cache:sweep         # снять только инкрементальные данные (~треть, без полной пересборки)
vp run cache:clean         # снять весь debug/release (полная пересборка, ~15 мин)
```

Ценовые предложения хранятся зашифрованными (INV-040, п. 40): мастер-ключ
приходит переменной `PRICE_ENCRYPTION_KEY` (в дев-стенде задан в compose,
на проде - в `.env`). Без ключа цены не читаются и не записываются, а его
потеря делает их нечитаемыми: копия ключа хранится отдельно от дампов БД.

## Проверки

```bash
vp check                   # формат + линт + типы + тесты фронта (codegen → lint → typecheck → test)
# Rust - в контейнере целиком: Windows-хост не линкует нативные бинарники
# (A-003), а кеш-тома общие с дев-стендом. Одна обвязка на check/clippy/test:
podman run --rm -v "$PWD":/w -w /w -e CARGO_TARGET_DIR=/target \
  -v tou-rent-cargo:/usr/local/cargo/registry -v tou-rent-target:/target \
  -v tou-rent-rustup:/usr/local/rustup rust:1.97 \
  sh -c "cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace"
```

Интеграционные тесты `testkit` идут против живой БД и без
`TESTKIT_DATABASE_URL` пропускаются. Чтобы прогнать их целиком, нужен
поднятый Postgres стенда и та же обвязка плюс сеть и адрес:

```bash
podman compose -f infra/compose/docker-compose.dev.yml up -d postgres
podman compose -f infra/compose/docker-compose.dev.yml --profile api run --rm api-migrate
podman run --rm --network tou-rent-dev_default -v "$PWD":/w -w /w \
  -e CARGO_TARGET_DIR=/target -e PRICE_ENCRYPTION_KEY=tou_rent_dev_price_key \
  -e TESTKIT_DATABASE_URL=postgres://tou_rent:tou_rent_dev@postgres:5432/tou_rent \
  -v tou-rent-cargo:/usr/local/cargo/registry -v tou-rent-target:/target \
  -v tou-rent-rustup:/usr/local/rustup rust:1.97 cargo test -p tou-testkit
```

Сквозные сценарии Правил (гейт G11) - `apps/e2e`, см. [его README](apps/e2e/README.md):

```bash
bun run --cwd apps/e2e e2e:install   # один раз: браузер chromium
bun run --cwd apps/e2e e2e           # § 9.1 + приемка контуров 2 и 3 (ТЗ § 10в)
```

Пайплайн (`.gitlab-ci.yml`) - это и есть ревью (арх. § 3): формат и линт,
миграции, кодоген без диффа, тесты против сервисной БД (включая паритет
календаря, аудит-инварианты и трассировку INV и FR), мутационное тестирование
домена, Schemathesis, Playwright, переводы, cargo-deny/`bun audit`/Trivy.
Все гейты G1–G16 работают в error-режиме (T31): допусков `allow_failure`
не осталось. Сам `.gitlab-ci.yml` и `deny.toml` - защищенные пути
(регламент А.4): правки - только отдельным MR с аппрувом инженера.
На живом раннере пайплайн еще не прогонялся (A-006, A-063).

Основной режим - пайплайн merge request (`workflow.rules`); пайплайн ветки
с открытым MR не задваивается. Гейты, работающие по диффу (G4 squawk по новым
миграциям, G2/SQL, G9 мутации), берут базу сравнения из `infra/ci/diff-base.sh`:
он либо дает ref, либо падает - гейт, не сумевший вычислить свой вход, обязан
быть красным, а не зеленым (T74). Полный прогон мутаций - по расписанию.

## Деплой

Прод-стенд (`infra/compose/docker-compose.prod.yml`, NFR-10) - одна машина:
Caddy с TLS от Let's Encrypt → web/api, PostgreSQL, Redis, RustFS, воркер
`jobs`; миграции накатывает `api-migrate` до старта api. Порядок деплоя,
переменные, провижининг хранилища, откат и разбор нештатных случаев -
в [infra/compose/README.md](infra/compose/README.md).

```bash
cd infra/compose && cp .env.prod.example .env   # заполнить секреты
./deploy.sh                                     # пулл → миграции → up -d → здоровье
```

Две особенности, о которых стоит знать заранее: `deploy.sh` отказывается
разворачивать что-либо, пока жива хоть одна комната торгов (обрыв WS-комнаты
посреди процедуры недопустим, п. 63–68; осознанный обход - `DEPLOY_FORCE=1`),
а при неудачной проверке здоровья возвращает стенд на последний тег, который
эту проверку проходил. Здоровье проверяется у обоих контейнеров трафика:
у api - `/api/v1/healthz`, у web - собственный маршрут `/healthz`.

Развернутый деплой на `rent.tou.edu.kz` еще не выполнялся (T49); сам прод-контур
целиком поднимался на машине разработчика (T75) - как это повторить, описано
там же, в README стендов.

Правила работы агента (источники истины, защищенные пути, запреты G2) - в [AGENTS.md](AGENTS.md).
