# infra

Все, что окружает код: стенды, образы, деплой, провижининг. Указатель, а не
описание - содержательные пояснения лежат рядом с самими файлами, чтобы
не расходиться с ними.

| Каталог    | Что там                                                           |
| ---------- | ----------------------------------------------------------------- |
| `compose/` | дев-стенд, прод-стенд и `deploy.sh` - [README](compose/README.md) |
| `docker/`  | образы прода: `api.Dockerfile` (Rust), `web.Dockerfile` (bun)     |
| `ci/`      | `diff-base.sh` - база сравнения для гейтов, работающих по диффу   |
| `zitadel/` | `provision.sh` - проект, роли, OIDC-клиент (FR-1502, ADR-0003)    |

Быстрые ответы на частые вопросы:

- **Поднять стенд для разработки** - `vp run stack:up` из корня; что именно
  поднимается и чем настраивается - [compose/README.md](compose/README.md).
- **Развернуть прод** - `infra/compose/deploy.sh`; переменные перечислены
  в его заголовке и в `compose/.env.prod.example`, порядок и разбор
  нештатных случаев - там же в README.
- **Сменить версию инфраструктурного образа** - только отдельным коммитом:
  теги пиньованы намеренно (T70), чтобы красный гейт означал «сломали код»,
  а не «сменилось окружение».
- **Секреты** в репозиторий не попадают (NFR-09): рабочие `.env`
  и `compose/.zitadel/oidc.env` живут на хосте и в `.gitignore`.

`.gitlab-ci.yml` лежит в корне репозитория (защищенный путь, регламент А.4);
`ci/diff-base.sh` - его единственная вынесенная часть.
